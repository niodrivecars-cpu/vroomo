# Task Template

Use for engineering tasks that will be reviewed or recorded.

## Goal
One sentence: what success looks like.

## Context
Why this task exists, what depends on it.

## Acceptance criteria
- [ ] Criterion 1 (testable)
- [ ] Criterion 2
- [ ] Criterion 3

## Steps
1. Investigate (read code/docs first — check `knowledge/`, `patterns/`).
2. Implement with tests (red → green).
3. Run the relevant gates (`execution/gates/`).
4. Record evidence.

## Gates to pass
- [ ] ruff / bandit / pip-audit / migrations
- [ ] tests
- [ ] security review (if security-touching)
- [ ] performance (if relevant)

## Evidence
Link the test results / scans / run outputs that prove completion.

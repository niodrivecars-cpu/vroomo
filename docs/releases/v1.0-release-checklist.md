# Release Checklist — v1.0 (first production release)

Gate to create the `v1.0.0` tag. **Do not tag** until every item is complete
and the sign-off table is filled. This is the product-side companion to
`docs/deployment/preflight-checklist.md` (environment gates) and
`docs/deployment/post-deploy-validation.md` (post-deploy gates).

## Before tagging

- [ ] Preflight checklist complete (all `[x]`, no blockers) —
      `docs/deployment/preflight-checklist.md`
- [ ] Production deployment succeeded on Hostinger shared hosting and stayed up
      for a soak period
- [ ] Post-deploy validation complete — `docs/deployment/post-deploy-validation.md`
- [ ] CI green on `release/1.0` for the shipped commit (ruff, bandit, pip-audit,
      migration-drift, 278 tests on MySQL, collectstatic, `check --deploy`)
- [ ] `makemigrations --check --dry-run` reports no drift
- [ ] Evidence manifest recorded for the release (`engineering/evidence/releases/`)
- [ ] Backup proven: a restore was tested in a scratch environment
- [ ] Rollback path documented and rehearsed (app + data)
- [ ] MySQL compatibility confirmed — no Postgres-only features (JSONB, GIN,
      `ArrayField`, raw SQL); `select_for_update` path verified on MySQL/InnoDB
- [ ] `PyMySQL>=1.2.0` pinned in `requirements.txt` (1.1.1 reports
      `version_info=(1,4,6)` and fails Django's `mysqlclient >= 2.2.1` import
      gate — the MySQL backend must load before anything else)
- [ ] `CHANGELOG.md` updated for the release (Keep a Changelog format, an
      `[Unreleased]` → `[X.Y.Z]` entry per release)

## Tagging

- [ ] Release branch `release/1.0` is the source of the tag
- [ ] Tag created and pushed: `git tag -a v1.0.0 -m "Vroom v1.0.0"` + `git push origin v1.0.0`
- [ ] (If VPS CD is ever re-enabled) tag push triggers the deploy; on Hostinger,
      hPanel Git auto-deploy pulls the tag/branch

## Deploy steps (in order)

1. [ ] Back up the current production database (fresh `backup.sh` run)
2. [ ] Verify environment variables on the target (.env / hPanel env)
3. [ ] Pull the tag (hPanel auto-deploy or `scripts/deploy-hostinger.sh`)
4. [ ] `manage.py migrate --noinput` — success, no partial migration
5. [ ] `manage.py collectstatic --noinput` — success
6. [ ] `manage.py compilemessages --ignore venv` — success
7. [ ] `manage.py check --deploy` — zero errors
8. [ ] Restart Passenger (`touch tmp/restart.txt`)
9. [ ] `GET /health/` returns HTTP 200

## Post-deploy (critical-path only, full list in post-deploy-validation.md)

- [ ] Login works
- [ ] Create driver, vehicle, booking, return, financial transaction
- [ ] Document upload + private download
- [ ] Audit log writes with the real client IP
- [ ] `https://<domain>/` served; HTTP redirects; `/media/` blocked

## Rollback plan

- **App-only regression:** checkout the previous ref/tag and
  `touch tmp/restart.txt` (ref recorded in `.deploy-state` by
  `deploy-hostinger.sh`).
- **Schema/data disaster:** restore from the pre-deploy backup
  (`scripts/restore.sh`), then redeploy the previous tag.
- **Decision point:** if the pre-deploy backup is missing or a restore has not
  been proven, **do not tag** — fix the gap first.
